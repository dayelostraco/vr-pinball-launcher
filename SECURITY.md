# Security

Report suspected vulnerabilities through this repository's **Security → Report a
vulnerability** page. Please avoid posting exploit details, credentials, private
paths, or personal backup archives in public issues. Include the affected version,
reproduction conditions, impact, and a minimal example that contains no tables or ROMs.

The current maintained release receives security fixes. Older releases should be
upgraded after reviewing the changelog and exporting a settings backup.

The launcher runs VPX and optional helpers with your Windows user's privileges.
Configuration files, table scripts and helpers are executable trust boundaries:
review their sources before installing them. Setup does not sandbox VPX tables.
ZIP backup checks validate structure, size and integrity; they do not establish
who created a backup. Full restores can change executable paths.

Optional downloads are pinned by URL and SHA-256 in `tools/download-lock.json`.
Updating the lock requires a reviewed upstream release and recorded provenance.
The AutoHotkey upstream installer and launcher installer are currently unsigned;
hash verification provides integrity, not an independent publisher signature.

CI scans source with Semgrep and checks Python dependencies with pip-audit and
Trivy. These scans do not comprehensively assess Unity/UPM or native DLLs. Native
component provenance and vendor advisories require separate release review.
Keep dependency notices current and record unsupported scanner coverage explicitly.

Experimental add-on DLLs have a separate `tools/native-lock.json` with reviewed hashes
and immutable upstream source URLs. CI checks their identity, AMD64 PE headers
and inventory, ASLR/NX declarations, section bounds and absence of writable
executable sections; add-on packaging rechecks hashes before creating its ZIP. The bridge
loads its library with explicit Windows DLL-search flags, without a current-folder
or PATH fallback. These controls prevent accidental replacement/search-path loading;
they do not establish that inherited unsigned binaries are free of vulnerabilities.

Release assets include a binary inventory generated by
`tools/write-release-inventory.ps1`: SHA-256 hashes, file versions, signature
status and the resolved Unity package lock for the standard player. The experimental
Touch ZIP carries its own native lock and is excluded from that inventory. Match bridge libraries to
their credited upstream sources when updating them. For the engine, review
[Unity security advisories](https://unity.com/security), including the
[CVE-2025-59489 advisory](https://unity.com/security/sept-2025-01), against the
exact editor and player version. A scanner reporting no recognized vulnerabilities
is not evidence that every proprietary or native dependency has been assessed.

See the [native dependency review](docs/native-assurance.md) for the specific
engine advisory disposition, inspected native properties and unresolved
source-build/signing requirements.

The standard installer excludes the experimental Touch scripts and native DLLs.
Existing add-ons are preserved during upgrades and retain their own trust boundary;
an upgrade does not silently remove or certify a user's installed add-on.
